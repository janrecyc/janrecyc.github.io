# Shop App Template

เทมเพลตแอพร้านรับซื้อของเก่า ที่บิ้วเป็น APK ได้อัตโนมัติผ่าน GitHub Actions
โครงสร้างเป็นแบบ **data-driven** — เพิ่มเมนู/รายการ/ข้อมูลในอนาคตได้โดยแก้ไฟล์ data เพียงไฟล์เดียว ไม่ต้องรื้อ HTML/CSS ที่มีอยู่

> โปรเจกต์นี้เริ่มจากเทมเพลต UI แอพ VPN แล้วปรับโครงสร้าง/ตัวแปรทั้งหมดมาเป็นแอพร้านรับซื้อของเก่าแล้ว (หน้า "ประเทศ" เดิม → "ร้านค้า") จากนั้นตัดหน้า "โปรไฟล์" ออก (ย้าย "บัญชี" ไปรวมกับหน้าตั้งค่า) แล้วแทนที่ด้วยหน้า "ตารางงาน" สำหรับนัดหมายไปรับซื้อของถึงบ้านลูกค้า

## โครงสร้างโปรเจกต์

```
www/
├── index.html          หน้าหลัก (shell — โครงเปล่า พร้อมใส่เนื้อหา)
├── shop.html            ร้านค้า (ดึงข้อมูลจาก data/shop-items.js)
├── schedule.html         ตารางงาน — นัดหมายไปรับซื้อของนอกร้าน (ดึงข้อมูลจาก data/schedule-jobs.js)
├── settings.html         การตั้งค่า (ดึงข้อมูลจาก data/settings.js — รวม "บัญชี" ของพนักงานไว้ที่นี่ด้วย)
│
├── css/
│   ├── tokens.css        สีธีม / ตัวแปรสว่าง-มืด — เพิ่มธีมใหม่ที่นี่
│   ├── layout.css        โครง app shell (แทบไม่ต้องแก้)
│   ├── nav.css           แถบเมนูล่าง/ข้าง (responsive)
│   └── components.css    ชิ้นส่วน UI ที่ใช้ซ้ำ (แถวรายการ, สวิตช์, ชิปฟิลเตอร์, การ์ดงานนัดหมาย ฯลฯ)
│
├── js/
│   ├── theme.js           จัดการสว่าง/มืด (ผูกกับสวิตช์อัตโนมัติไม่ว่าจะ render จากไหน)
│   ├── data/               ★ ที่ใส่ "ข้อมูล" ในอนาคต
│   │   ├── nav.js          รายการเมนูล่าง/ข้าง — เพิ่มแท็บใหม่ที่นี่
│   │   ├── settings.js     รายการในหน้าตั้งค่า (6 หมวด รวมบัญชี) — เพิ่มแถวใหม่ที่นี่
│   │   ├── shop-items.js   รายการของที่รับซื้อ/ขายออก (ว่างไว้ก่อน) — เพิ่มของที่นี่
│   │   ├── shop-tabs.js    4 แท็บของร้านค้า (รับซื้อ/ขายออก/คัดแยก/ประวัติการซื้อขาย)
│   │   ├── schedule-jobs.js  รายการงานนัดหมาย (ว่างไว้ก่อน) — เพิ่มงานที่นี่
│   │   └── schedule-tabs.js  4 แท็บของตารางงาน (วันนี้/รอดำเนินการ/เสร็จแล้ว/ยกเลิก)
│   ├── components/         ★ ตัว render ข้อมูลเป็น HTML (ปกติไม่ต้องแก้)
│   │   ├── nav.js
│   │   ├── section-list.js    render "หมวด+แถว" ให้หน้าตั้งค่า (และหน้าอื่นในอนาคตที่โครงเหมือนกัน)
│   │   ├── shop-item-list.js
│   │   ├── schedule-job-list.js  การ์ดงานนัดหมาย (ลูกค้า/ที่อยู่/เวลา/สถานะ)
│   │   ├── tab-filter.js   แถบชิปแท็บ ใช้ร่วมกันทั้ง shop.html และ schedule.html
│   │   └── search-bar.js   ปุ่มค้นหา + ช่องค้นหาที่ยุบ/ขยายได้ (ใช้ซ้ำได้ทุกหน้า)
│   └── pages/               ★ ตัวเชื่อม data+component เฉพาะหน้า
│       ├── shop-page.js      ผูกค้นหา + แท็บ + รายการร้านค้าเข้าด้วยกัน
│       └── schedule-page.js  ผูกค้นหา + แท็บ + รายการงานนัดหมายเข้าด้วยกัน
│
└── assets/icons/          ไอคอน/รูปในอนาคต
```

### หน้าตารางงาน — นัดหมายไปรับซื้อของนอกร้าน

หน้าตารางงานมี: ปุ่มค้นหา (มุมขวาบน) + แถบแท็บ 4 ปุ่ม (วันนี้ / รอดำเนินการ / เสร็จแล้ว / ยกเลิก) + การ์ดงานแต่ละใบ (ชื่อลูกค้า, ที่อยู่, วันเวลานัด, เบอร์โทร, badge สถานะ)

- **แท็บ "วันนี้" ทำงานต่างจากอีก 3 แท็บ**: กรองจาก `job.date` ตรงกับวันที่ปัจจุบัน ส่วนอีก 3 แท็บกรองจาก `job.status` — งานหนึ่งใบเป็น "วันนี้" และ "รอดำเนินการ" พร้อมกันได้ ตรรกะทั้งหมดอยู่ใน `js/pages/schedule-page.js`
- **เพิ่มงานนัดหมาย**: แก้ `js/data/schedule-jobs.js` เติม object ในอาเรย์ เช่น
  ```js
  { customer: 'ลุงสมชาย', phone: '081-234-5678', address: 'บ้านเลขที่ 12 ถ.สุขุมวิท',
    date: '2026-08-15', time: '14:00', status: 'pending', note: 'เศษเหล็กประมาณ 200 กก.' }
  ```
- **ยังไม่มี**: การกดเข้าไปดู/แก้ไขรายละเอียดงานแต่ละใบ (ตอนนี้เป็นการ์ดแสดงผลอย่างเดียว), การนำทางไปยังที่อยู่ลูกค้า, การแจ้งเตือนก่อนถึงเวลานัด — ทั้งหมดนี้เป็นจุดต่อยอดในอนาคต

### หน้าร้านค้า — โครงที่วางไว้สำหรับ 4 แท็บย่อย

หน้าร้านค้าตอนนี้มี: ปุ่มค้นหา (มุมขวาบน) + แถบแท็บ 4 ปุ่ม (รับซื้อ / ขายออก / คัดแยก / ประวัติการซื้อขาย) + รายการของ ที่กรองตามแท็บที่เลือกและคำค้นหาพร้อมกัน

- **ตอนนี้**: กดแท็บแค่กรองรายการเดิม (client-side filter) เพราะยังไม่มีข้อมูลจริง — "รับซื้อ" คือแท็บ default (แสดงทุกรายการ, เดิมคือ "ทั้งหมด")
- **เพิ่มของ**: ใส่ `tags: ['sell-out']` (หรือ `'sorting'`) ในแต่ละ object ที่ `js/data/shop-items.js` ให้ตรงกับ `tag` ใน `js/data/shop-tabs.js`
- **⚠️ ข้อควรระวังเรื่อง "ประวัติการซื้อขาย"**: ตอนนี้ยังผูกกลไกเดียวกับอีก 3 แท็บ (แค่กรองรายการของเดิม) แต่ในแอพจริง ประวัติการซื้อขายควรเป็นข้อมูลคนละชนิด (รายการธุรกรรม: วันที่/ลูกค้า/ยอดเงิน ไม่ใช่รายการของ) — พอจะทำจริงแนะนำให้แยกไฟล์ข้อมูลใหม่ เช่น `js/data/transactions.js` และ render function ของตัวเอง แทนที่จะยัดผ่าน `shop-item-list.js`
- **ถ้าต้องการให้แต่ละแท็บเป็น "หน้าย่อย" จริง ๆ** (ดีไซน์/เนื้อหาต่างกันไปเลย ไม่ใช่แค่กรองรายการ) จุดที่ต้องแก้มีจุดเดียวคือ `js/pages/shop-page.js` — ฟังก์ชัน `applyView()` เปลี่ยนจาก filter ธรรมดาเป็น router สลับเนื้อหาตามแท็บที่เลือกได้เลย ไม่กระทบไฟล์อื่น

### หน้าตั้งค่า — รวม "บัญชี" ของพนักงานไว้ที่นี่แล้ว

เดิมมีหน้า "โปรไฟล์" แยกไว้สำหรับเปลี่ยนรหัสผ่าน/สลับบัญชี/ออกจากระบบ แต่ตัดหน้าโปรไฟล์ออกแล้ว (ใช้ที่ในเมนูล่างไปทำ "ตารางงาน" แทนเพราะใช้งานบ่อยกว่า) รายการเหล่านั้นย้ายมาเป็นหมวด **"บัญชี"** ในหน้าตั้งค่าแทน — ยังกดไม่ได้จริงเหมือนแถว `link` อื่น ๆ รอระบบ auth จริง

## เพิ่มข้อมูลในอนาคตยังไง (ไม่ต้องรื้อระบบ)

**เพิ่มของที่รับซื้อ/ขายออก** → แก้ `js/data/shop-items.js` เติม object ในอาเรย์ เช่น
```js
{ icon: '🔩', name: 'เหล็ก', price: '12', unit: 'บาท/กก.', tags: ['sell-out'] }
```
หน้า `shop.html` จะ render ให้เองอัตโนมัติ

**เพิ่มงานนัดหมาย** → แก้ `js/data/schedule-jobs.js` (ดูตัวอย่างในหัวข้อ "หน้าตารางงาน" ด้านบน)

**เพิ่มรายการตั้งค่า** → แก้ `js/data/settings.js` เติม object ใหม่ ระบุ `type` เป็น `toggle` / `select` / `value` / `link`

**เพิ่มแท็บเมนูล่างใหม่** → แก้ `js/data/nav.js` เติมแท็บ แล้วสร้างไฟล์หน้าใหม่ (คัดลอกโครงจาก `shop.html` หรือ `schedule.html` เป็นต้นแบบ ถ้าต้องการค้นหา+แท็บ, หรือ `settings.html` ถ้าต้องการแบบ "หมวด+แถว") ทุกหน้าจะเห็นแท็บใหม่ทันทีเพราะเมนูโหลดจากไฟล์เดียวกัน

**เพิ่ม type ใหม่ที่ settings ยังไม่รองรับ** → แก้ที่ `js/components/section-list.js` จุดเดียว (เพิ่ม `case` ใน switch)

**เพิ่มแท็บ+รายการแบบ shop/schedule ในหน้าใหม่** → ใช้ `js/components/tab-filter.js` + `js/components/search-bar.js` ร่วมกันได้เลย เขียนแค่ data file, list-renderer, และ page controller ของตัวเอง (ดู `schedule-*` เป็นตัวอย่าง)

## วิธีใช้งาน

### 1. ทดสอบในเบราว์เซอร์ก่อน
เปิดไฟล์ `www/index.html` ตรง ๆ ในเบราว์เซอร์ก็ดูหน้าตาได้เลย

### 2. อัปโหลดขึ้น GitHub
```bash
git init
git add .
git commit -m "init shop app template"
git branch -M main
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
```
> ถ้า repo มีเว็บ/โปรเจกต์อื่นอยู่แล้ว ให้ push ไฟล์ทั้งหมดในนี้ไปไว้ที่ **root ของ repo** ไม่ใช่ในโฟลเดอร์ย่อย ไม่งั้น `npm install` ใน workflow จะหา `package.json` ไม่เจอ

### 3. ให้ GitHub Actions บิ้วให้อัตโนมัติ
พอ push ขึ้น branch `main` เวิร์กโฟลว์ `.github/workflows/build.yml` จะรันเอง:
- ติดตั้ง Node + JDK
- เพิ่ม Android platform ด้วย Capacitor (`npx cap add android`)
- sync ไฟล์เว็บเข้าโปรเจกต์ Android
- **ขยับเลขเวอร์ชันแอปอัตโนมัติ** (`versionCode`/`versionName` ในหัวข้อถัดไป)
- บิ้ว `app-debug.apk`
- อัปโหลดเป็น Artifact ให้โหลดจากแท็บ **Actions** ของ repo

ไม่ต้องมีเครื่อง Android Studio เองก็บิ้วได้ เพราะรันบนเครื่อง GitHub

#### เลขเวอร์ชันแอปเพิ่มอัตโนมัติทุกครั้งที่บิ้ว
เพราะ `android/` ถูกสร้างใหม่ทุกครั้ง (ไม่ commit เก็บไว้ — ดู `.gitignore`) `versionCode`/`versionName` เลยรีเซ็ตเป็นค่าเริ่มต้น `1` / `"1.0"` ของ Capacitor เสมอถ้าไม่มีอะไรมาแก้ ทำให้เครื่องที่ติดตั้งแอปไว้แล้วเห็นว่า "เวอร์ชันเดิม" ทุกรอบ (ขึ้น "อัปเดต" ไม่ได้จริง หรือบางทีก็สับสนว่าติดตั้งซ้ำไม่ได้)

เวิร์กโฟลว์แก้เรื่องนี้ให้แล้ว — ขั้นตอน "Bump app version" จะ patch `android/app/build.gradle` ทุกครั้งก่อนบิ้ว โดยใช้เลขรันของ GitHub Actions (`github.run_number` เพิ่มขึ้นทุกครั้งอัตโนมัติ ไม่มีวันซ้ำ):
- `versionCode` → เลขรัน (เช่น 12, 13, 14, ...)
- `versionName` → `1.0.<เลขรัน>` (เช่น `1.0.12`)

ไม่ต้องทำอะไรเพิ่ม แค่ push ใหม่แล้วรอบิ้ว เครื่องที่มีแอปเวอร์ชันเก่าอยู่จะเห็นเป็น "อัปเดต" ให้ถูกต้องเสมอ ถ้าอยากเปลี่ยนรูปแบบเลขเวอร์ชัน (เช่นอยากคุมเป็น 1.1, 2.0 เอง) แก้ที่ step "Bump app version" ในไฟล์ `.github/workflows/build.yml`

### 4. รองรับทุกอุปกรณ์/การหมุนจอ
เลย์เอาต์เป็นแบบ responsive เต็มรูปแบบ ไม่ได้ล็อกทิศทางใด ๆ และล็อกความสูงเท่าจอพอดี (`.app { height: 100dvh; overflow: hidden }`) ทำให้เมนูล่าง/ข้างตรึงอยู่กับที่เสมอ ไม่ว่าจะ scroll เนื้อหาหน้าไหนก็ตาม:
- **แนวตั้ง (มือถือ)** — เมนูอยู่แถบล่าง
- **แนวนอน / แท็บเล็ต / จอกว้าง** — เมนูย้ายไปเป็นแถบข้างซ้ายอัตโนมัติ เนื้อหาขยายเต็มพื้นที่ที่เหลือ
- ใช้ `env(safe-area-inset-*)` ทุกด้าน รองรับรอยบาก/แถบนำทางท่าทาง

ปรับ breakpoint ได้ที่ `www/css/layout.css` และ `www/css/nav.css` ส่วน `@media (orientation: landscape)`

### 5. เปลี่ยนไอคอน / ชื่อแอพ / appId
แก้ที่ `capacitor.config.json` (`appId`, `appName`) ก่อน push ครั้งแรก — ตอนนี้ใส่ค่าตัวอย่างไว้ (`com.example.scrapshop` / "Scrap Shop App") ควรเปลี่ยนเป็นชื่อร้านจริงก่อน build
เปลี่ยนไอคอนจริงทีหลังได้ที่ `android/app/src/main/res/mipmap-*`

## หมายเหตุ
โค้ดนี้เป็น **เทมเพลต UI + โครงสร้างข้อมูลเปล่า ๆ** เท่านั้น (`index.html` ยังเป็น shell ว่าง, รายการรับซื้อ/ขายออกใน `shop.html`, งานนัดหมายใน `schedule.html`, และค่าในหน้าตั้งค่ายังไม่มีข้อมูลจริง) รอเติมเนื้อหาและต่อ backend จริงตามที่ออกแบบธุรกิจไว้

## เอกสารกฎหมาย (ร่าง)
`legal/privacy-policy.md` และ `legal/terms-of-service.md` เป็น**ฉบับร่างเบื้องต้น** สำหรับนโยบายความเป็นส่วนตัวและข้อกำหนดการใช้งาน ที่หน้าตั้งค่า (`เกี่ยวกับแอพ`) จะลิงก์ไปในอนาคต — ต้องเติมข้อมูลในวงเล็บ `[ ]` ให้ครบและ**ให้ทนายความตรวจสอบก่อนเผยแพร่จริง** ทั้งสองไฟล์ยังไม่ได้ hosted และยังไม่ได้ผูกลิงก์กับแถว `link` ในหน้าตั้งค่า
